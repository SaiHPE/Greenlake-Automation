# Work packet BL-24 — slice 1: array status and performance at handover

A brief for building the first slice without making decisions. Every decision is already taken in
[SPEC-026](../specs/SPEC-026-handover-status-and-performance.md) and
[ADR 0019](../adr/0019-handover-report-from-the-array.md) (accepted 2026-11-17 by the owner, with the
seven changes listed at its top). Background: [research note](../research/2026-11-16-health-performance-reporting.md).
If something here disagrees with the spec, the spec wins; if the spec disagrees with a capture, the
capture wins and you correct the spec in the same pull request.

## Goal

When the as-built is generated, the tool also reads the array's New alerts, capacity in use and 24
hours of System Reporter performance, over the read-only SSH client, and writes a section *Array
status and performance at handover* into the document, with a short *Status at handover* block on
the As-built page. Nothing new is asked of the operator. Nothing on the array changes.

**The first slice:** add `showalert`, `srstatcpu`, `srstatport` and `srstatvv` to the allowlist
with the tests below; alerts, capacity and three short performance tables in the as-built, plus the
summary block on the As-built page; then one *Verify only* live run on a lab array. Remote Copy
figures (SPEC-026 R7) and `srstatrcvv` are not in it.

## Steps (each one passes `scripts/check.py` on its own; one commit each)

**Step 0 — capture script (done).** `lab/handover_capture.py`, read-only, modelled on
`lab/rcip_pair_capture.py`: SSH as the lab user from `.env`, `help` for each report, then every
command in SPEC-026 R3 and `showalert -d`, each saved to a file named after the command, zipped to
`~/Downloads`. It refuses any command not starting with `show`, `srstat`, `checkhealth` or `help`.
Only the owner runs it. A later run should also save `showport`, so R6's port rule has a capture
from the same night (SPEC-026 §2a, *Not captured yet*).

**Step 1 — fixtures (done).** The owner's captures in `tests/fixtures/handover/<array>/`, each with
a README (array model, OS, date, idle or loaded, which alerts are open), scrubbed.

**Step 2 — allowlist.** Add the four base names `showalert`, `srstatcpu`, `srstatport`, `srstatvv`
to `ALLOWED_COMMANDS` with a comment `# SPEC-026: alerts and System Reporter reports (read-only)`.
In `tests/unit/test_cli_allowlist.py`, beside the help review already there: each of the four
passes `refusal()`; `srstatrcvv` and each never-added command in the decisions table is refused;
`srstatvv; removevv x` is refused (metacharacter); and, as LESSONS 46 asks, one allowed name with
an acting option (`showtarget -rescan`, if BL-46 has merged). The help review needs no change unless
a new capture adds an option. Add the ADR 0001 addendum. Say in the commit message: "adds four read
commands to the SSH allowlist".

**Step 3 — parsers (done).** `application/documents/handover.py`: `parse_alerts(text) -> list[Alert]`,
`parse_space(text) -> Space`, `parse_srstat_summary(text) -> SrSummary` (one parser for all
`srstat*` summaries; rows keyed by statistic and group), and per report `cpu_by_node`,
`ports_by_port`, `volumes_total`, `rc_by_group`. Anything that is not the expected report raises
`UnreadableReport` with the array's first line, never an empty or zero result. Pure functions, no
I/O. Tests in `test_handover_parse.py`, pinned to the step 1 files.

**Step 4 — reads and summary.** In `documents/steps.py`, after the existing as-built reads, run the
five R3 reads, each into its own `AsBuiltData` field, errors into `read_errors` keyed by the
command. No `srstatrcvv`. In `handover.py`:
- the array's UTC offset from the first System Reporter summary that parsed: local time from
  `SrSummary.start_text` minus the UTC `start` from its epoch (+05:30 on every capture); `None`
  when none parsed. No `zoneinfo`, no zone name, no abbreviation.
- *Before this run* per alert: `Alert.first_seen_local` minus the offset, against the run's
  creation time; *unknown* when the offset is `None`.
- the cloud alert: the New alert with message code `0x060000a`, or none.
- the alert table: Major, Critical and Fatal in full; the rest grouped by message code and severity
  (count, first and latest occurrence, one sample).
- the ready ports from `showport` (already read) and the one line for the rest.
- `summarise(...) -> HandoverSummary` with the R10 fields and `idle` (host ports, SPEC-026 R6).
Tests: unit tests on the captures for each item above (SPEC-026 §4 gives the expected counts);
extend the fake `_Cli` in `test_asbuilt_provisioned.py` (it already drives `_collect_asbuilt`); one
test that a refused command lands in `read_errors` and the others still read.

**Step 5 — document section.** `_add_handover_section(doc, data, warnings)` after the `checkhealth`
heading, per SPEC-026 R4–R6 and R8–R9, using `_read_failed`, `_h1`, `_para`, `_table`. Tests in
`test_asbuilt_handover.py`: heading order; verdict sentences with and without the cloud sentence;
the alert table's full and grouped rows and the `showalert -d` pointer; the Major-alert warning; the
performance sentence always and the idle sentence only below `IDLE_IOPS`; the port line; the three
cloud lines; a failed read shows the named line and no `0`; no section text says *health* outside
the command name.

**Step 6 — event and page.** Add `handover` to the `asbuilt.generated` data (R10), its type in

rebuild `frontend/dist`. Check by hand with `npm run dev` against a backend fed the fixtures.

## LESSONS traps

- **24** Alerts persist, state does not: always print the alert time and the *Before this run* flag.
- **29** Read the SDK function before using it: `getCPGStatData` returns zeros on any error. Not used.
- **28** A fake proves our code, not the array: parsers only against real captures.
- **39** Judge a command by the array's own refusal text, not by the absence of "Error".
- **46** An allowlist of names is not an allowlist of actions: the help review pins every option.
- **3 / 27** A failed or empty read must say so in words; never render it as an idle `0`.
- **9** No new stored artifact; the docx and event are already bounded.
- **12, 13** Check the page in the running app, and confirm which bundle the browser loaded.
- **20** The UI never says *health*; write *status*.
