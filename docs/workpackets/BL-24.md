# Work packet BL-24 — slice 1: array status and performance at handover

A brief for building the first slice without making decisions. Every decision is already taken in
[SPEC-026](../specs/SPEC-026-handover-status-and-performance.md) and
[ADR 0019](../adr/0019-handover-report-from-the-array.md) (PROPOSED: do not start until the owner
has said yes to the ADR). Background: [research note](../research/2026-11-16-health-performance-reporting.md).
If something here disagrees with the spec, the spec wins; if the spec disagrees with a capture, the
capture wins and you correct the spec in the same pull request.

## Goal

When the as-built is generated, the tool also reads the array's alerts, capacity in use and 24 hours
of System Reporter performance, over the read-only SSH client, and writes a section *Array status
and performance at handover* into the document, with a short *Status at handover* block on the
As-built page. Nothing new is asked of the operator. Nothing on the array changes.

## Steps (each one passes `scripts/check.py` on its own; one commit each)

**Step 0 — capture script (owner runs it).** Write `lab/handover_capture.py`, read-only, modelled
on `lab/rcip_pair_capture.py`: SSH as the lab user from `.env`, run `help showalert`,
`help srstatcpu`, `help srstatport`, `help srstatvv`, `help showsys`, then every command in SPEC-026
R3 and `showalert -d`, save each to a file named after the command, zip to `~/Downloads`. It must
refuse any command not starting with `show`, `srstat` or `help`. Tests: none (lab script), but run
`ruff`. **Stop here** and ask the owner to run it on the lab arrays (one idle, one with I/O or an
open alert if the lab has one). You may not run it yourself.

**Step 1 — fixtures.** Unzip the owner's capture into `tests/fixtures/handover/<array>/` with a
README (array model, OS, date, idle or loaded, which alerts are open). Sanitise: no customer name,
no password; lab addresses are allowed as in `rc_pair/`. Correct SPEC-026 R3 where the help shows a
different option name. Tests: none yet; check.py passes.

**Step 2 — allowlist.** Add the five base names to `ALLOWED_COMMANDS` with a comment
`# SPEC-026: alerts and System Reporter reports (read-only)`. New `tests/unit/test_cli_allowlist.py`:
each of the five passes `refusal()`; each never-added command in the decisions table is refused;
`srstatvv; removevv x` is refused (metacharacter). Add the ADR 0001 addendum. Say in the commit
message: "adds five read commands to the SSH allowlist".

**Step 3 — parsers.** `application/documents/handover.py`: `parse_alerts(text) -> list[Alert]`,
`parse_space(text) -> Space`, `parse_srstat_summary(text) -> list[SummaryRow]` (one parser for all
`srstat*` summaries; rows keyed by group, columns avg / 95% / max), and
`summarise(...) -> HandoverSummary` with the R10 fields and `idle`. Pure functions, no I/O.
Tests in `test_handover_parse.py`, pinned to the step 1 files and to
`tests/fixtures/rc_pair/D22U27/srstatrcvv_hourly.txt` (all zeros: `idle` is true). Parse the
array's words for severity; do not invent a severity list.

**Step 4 — reads.** In `documents/steps.py`, after the existing as-built reads, run the R3 commands
(the `rcvv` one only when the run has a Replication tab), each into its own `AsBuiltData` field,
errors into `read_errors` keyed by the command. Pass the run's creation time for *Before this run*.
Tests: extend the fake `_Cli` in `test_asbuilt_provisioned.py` (it already drives
`_collect_asbuilt`); one test that a refused command
lands in `read_errors` and the others still read.

**Step 5 — document section.** `_add_handover_section(doc, data, warnings)` after the `checkhealth`
heading, per SPEC-026 R4–R9, using `_read_failed`, `_h1`, `_para`, `_table`. Remote Copy rows in
the replication section next to `_add_link_check`. Tests in `test_asbuilt_handover.py`: heading
order, verdict sentences, Major-alert warning, idle sentence, a failed read shows the named line and
no `0`, no section text says *health* outside the command name.

**Step 6 — event and page.** Add `handover` to the `asbuilt.generated` data (R10), its type in
`api.ts`, the *Status at handover* block on `AsBuiltStep.tsx`. Run `npm run typecheck`. Do not
rebuild `frontend/dist`. Check by hand with `npm run dev` against a backend fed the fixtures.

**Step 7 — docs.** SCOPE area 8: *built, pending live run* for slice 1. ARCHITECTURE: one line for
`documents/handover.py`. The PR says *built, pending live run* and keeps `needs live run`.

## LESSONS traps

- **24** Alerts persist, state does not: always print the alert time and the *Before this run* flag.
- **29** Read the SDK function before using it: `getCPGStatData` returns zeros on any error. Not used.
- **28** A fake proves our code, not the array: parsers only against real captures.
- **39** Judge a command by the array's own refusal text, not by the absence of "Error".
- **3 / 27** A failed or empty read must say so in words; never render it as an idle `0`.
- **9** No new stored artifact; the docx and event are already bounded.
- **12, 13** Check the page in the running app, and confirm which bundle the browser loaded.
- **20** The UI never says *health*; write *status*.
