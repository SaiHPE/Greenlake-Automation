## Steps (each one passes `scripts/check.py` on its own; commit after each)

**Step 1 — Regional client.** Add the buckets and, in `clients.py`:
`FILE_REGIONS = ("us-west", "eu-west", "eu-central", "ap-northeast")`;
`regional_base_url(region)` returns `f"https://{region}.api.greenlake.hpe.com"` or raises
`ValueError` with the SPEC-029 R1 sentence; `make_regional_greenlake(settings, region)` returns a
`GreenLakeHttpClient` on that URL with the same `OAuthClientCredentials` arguments as `make_greenlake`.
Tests (`tests/unit/test_file_check.py`): each of the four regions gives its URL; `us-east` and `""`
raise with the sentence; the buckets exist with capacity 60.

**Step 2 — Storage Fleet adapter.** `StorageFleetClient(http).list_devtype7_systems()`: GET
`/storage-fleet/v1alpha1/devtype7-storage-systems`, `bucket="fleet_read"`,
`params={"limit": 100, "offset": n}`, loop while collected `< total` (stop when a page is empty or
`total` is absent). Returns the raw `items` dicts. Tests (contract): path, bucket and params of the
first call; two pages joined (`total: 3`, pages of 2 and 1); a body with no `total` stops after one
page.

**Step 3 — File Storage adapter.** `FileStorageClient(http)` with `list_filesystems(devtype, system_id)`
and `list_file_shares(devtype, system_id)`; `devtype` must be `"devtype4"` or `"devtype7"`
(`ValueError` otherwise). Paths `/file-storage/v1alpha1/{devtype}-storage-systems/{system_id}/filesystems`
and `/file-shares`, `bucket="file_read"`, the same paging as step 2. No other methods. Tests
(contract): paths for both device types, refusal of `devtype9`, paging, and that the class has no
attribute named `create*`, `update*` or `delete*`.

**Step 4 — Domain models.** In `domain/filestorage.py`, reuse `domain.models.CheckStatus`
(`PASS`, `WARN`, `FAIL`, `SKIP`; SPEC-029's SKIPPED is `SKIP`). `FileCheck(name, status, message, remediation="")`;
`FileSystemRecord(id, name, state, share_count, hard_limit_bytes)` with `from_api(dict)`;
`FileShareRecord(id, path, protocols, state, end_point, filesystem, access_clients)` with
`from_api(dict)` (`filesystem` is the `fileSystem` object kept as a dict: its fields are not
documented); `FileCheckReport(serial, region, matched_by, system_id, checks, filesystems, shares)`
with `ok` (no FAIL) and `to_json()`. Tests: `from_api` on the documented examples (research §3);
missing optional fields give `None`, never a `KeyError`.

**Step 5 — The check service.** `FileSystemCheckService(token_provider, devices, service_catalog,
fleet, files, now=datetime.now)`, `run(serial, region)`: R3's order; R4's match; R5's table row by
row, one private method per check; a 401/403 (`httpx.HTTPStatusError`) on fleet or file reads gives the
FAIL that names the permission; `httpx.ConnectError` gives the unreachable FAIL; a check that
depends on a failed one is SKIPPED with the reason. Compare the device's `application.id` with the
provisions; **never** take `provisions[0]`. Optional `capture: Callable[[str, dict], None]` called
with every raw body; `redact_capture` removes `customerId`, `tenantWorkspaceId`, `subscription[].key`,
and e-mail and phone fields under `status.supportContact`, at any depth. Tests (fakes only): every R5
row in each status it can take; R4 by `id`, by `logicalClusterSerialNumber`, none (message lists the
systems), two (FAIL, nothing picked); a 403 on filesystems names `file-storage.file-system.read`; a
404 with a JSON body is *reachable*; R7: a recording fake over a full PASS run sees only GET;
`redact_capture` on a body holding all five fields.

**Step 6 — The CLI command.** `file-check` in `cli/main.py`: options `--serial` (required), `--region`
(required), `--json PATH`, `--capture DIR`. Refused region and missing credentials exit 2 with the
sentences; then the table, the filesystem list, the share list; `--json` writes `report.to_json()`;
`--capture` writes `NN-<what>.json` files through `redact_capture`; exit 1 when any FAIL. Build the
service through a module-level factory function so the test can monkeypatch it. Tests
(`typer.testing.CliRunner`, a fake service): exit codes 0, 1, 2; the JSON file; capture file names;
the subscription key never appears in the output.

**Step 7 — Docs.** SPEC-029 status: *built <date>, pending live run*. Nothing else; the owner updates
SCOPE and the tracker. The pull request says *built, pending live run*, keeps `needs live run`.

## Traps (from LESSONS.md)

- **27** — a 401, 403 or 404 with a body is a service that answered. Only a connection failure is
  "unreachable".
- **28** — fakes prove the calls we make, not the answers we get. Do not "fix" a parser to a guessed
  shape; leave it to the captures.
- **36** — never let "the first one" or "empty" decide: no `provisions[0]`, no "first system that
  matches", no "all systems" when nothing matched.
- **41** — the serial-to-system join is decided in one function, used everywhere.
- **26 / 34** — quote what the API returned (`assignedState`, `cloudState`, `errMessage`) in the
  sentence; keep the identifying fields next to each verdict.
- **21** — captures carry workspace ids and contacts: redact before anything reaches git.
- **30** — this slice must not grow a write method "for later". Writes need ADR 0022 accepted and
  their own spec.
