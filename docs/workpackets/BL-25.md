# Work packet BL-25 — VLAN-tagged iSCSI addresses on the array's ports

**Read first:** [SPEC-024](../specs/SPEC-024-iscsi-vlans.md) (what to build, every sentence),
[ADR 0017](../adr/0017-iscsi-vlan-write-plane.md) (PROPOSED: how the write goes), `AGENTS.md`,
`docs/LESSONS.md` entries 6, 7, 28, 29, 31, 37, 39, 41. **Tests:** `tests/unit/test_iscsi_vlans.py`.

## Goal

The engineer lists VLAN-tagged iSCSI addresses on a new *iSCSI network* tab; the tool plans them
against what the array has, adds them after the operator approves, gives the undo lines, checks them
in Verify and writes them into the as-built. The switch side is a sentence for the network team; the
tool never writes a switch.

## Decisions already taken (do not reopen them in code)

- Scope, sheet columns, every refusal and conflict sentence, plan states, step placement: SPEC-024.
- Reads use the read-only SSH client; no read allowlist change (SPEC-024 R2).
- iSCSI ports only. Never change a port's role, an existing VLAN interface, or the untagged address.
- The write plane is **not decided**: ADR 0017 is PROPOSED. Steps 1 to 6 below do not need it. Do not
  start step 7 until the owner has marked ADR 0017 accepted and named the option.
- Shared with SPEC-025 (BL-26, peer ports): `PortRole` from `parse_showport_roles` is the one source of
  a port's role. If SPEC-025 merged first and already added an *Array ports* step, add a section to
  it instead of a second step.

## Steps

Each step is one pull-request-sized commit that passes `scripts/check.py` on its own. When a step
turns tests green, **delete their `@NOT_BUILT` / `@NOT_CAPTURED` marker** in the same commit (strict
xfail fails the suite when a test passes with its marker on: that is how you know).

**Step 0 — Captures and the decision (owner, lab).** Ask the owner before anything touches the lab.
`lab/iscsi_vlan_capture.py` is read-only (show commands, help, WSAPI GETs). It writes
`~\Downloads\iscsi_vlan_capture.zip` with `E18U31/` and `D22U27/` folders. Copy them to
`tests/fixtures/iscsi_vlan/E18U31/` and `.../D22U27/`, scrub (no passwords, no customer names; lab
addresses are fine), and write `tests/fixtures/iscsi_vlan/README.md`: where, when, by which script,
and the facts each file settles (the `showport -iscsivlans` columns, the create and delete forms in
`help controliscsiport`, what `GET /ports/<n:s:p>/iSCSIVlans/` answers on a port with no VLAN). If no
lab array has a VLAN interface, say so in the README: the parser is then pinned to the header line
and the empty answer only, and the live run (step 9) captures a tagged row. The owner reads the HPE
WSAPI guide for OS 10.5 and decides ADR 0017.

**Step 1 — Models and the sheet.** Create `domain/network.py` exactly as SPEC-024 §4. Add the field to
`ProvisioningIntent`. In `init_sheet.py` copy the Replication network tab pattern:
- columns `("port", "Port (N:S:P)", True)`, `("vlan", "VLAN ID", True)`, `("ip", "iSCSI address", True)`,
  `("netmask", "Netmask", True)`, `("gateway", "Gateway (optional)", False)`;
- the template writes the tab after *Replication network* with the intro sentence of R1, 8 blank
  rows, and column A (Port) as text (`number_format = "@"`);
- `_parse_iscsi_network_tab` runs where `_parse_provisioning_tab` runs and fills `iscsi_network`.
  Check in this order, stopping at the first refusal: missing cells, port shape (reuse the regex of
  `_parse_network_tab`), VLAN ID (`str.isdigit()` and 1 to 4094), address (`_ipv4`), netmask
  (`_netmask`), gateway shape, gateway on the network, network or broadcast address, port+VLAN
  twice, address twice; then the two cross-row rules. Network text is `ipaddress.ip_network(f"{ip}/{mask}", strict=False)`.
  Use the R1 sentences word for word;
- Excel may store a port as a time: `_cell_text` already turns it back for a `port` key; check it does here.
Turns green: `test_the_iscsi_network_tab_parses_into_the_intent`,
`test_a_wrong_iscsi_network_row_is_refused_with_a_sentence` (all cases),
`test_the_template_has_the_iscsi_network_tab_with_the_port_column_as_text`.

**Step 2 — `parse_showport_iscsi`.** In `discovery.py`, beside `parse_iscsi_ips`. Rows start with an
N:S:P. Columns by header name, not position: two layouts exist (`... STGT VLAN` in
`tests/unit/test_storage_services.py` `_SHOWPORT_ISCSI`, `... STGT VLANs Peer_Enabled` in
`tests/fixtures/rc_pair/E18U31/showport_iscsi.txt`). `0.0.0.0` means unset (normalise to `""`);
`Peer_Enabled` `Y` is `True`, missing is `False`. Prose such as *"There is no specified port
information."* gives `[]`. Do not change `parse_iscsi_ips`. Turns green:
`test_showport_iscsi_gives_mask_gateway_and_the_peer_flag_from_the_e18u31_capture`.

**Step 3 — The plan.** `plan_iscsi_vlans(requests, view)` in `iscsi_network.py`, pure. Per request, in
order, the first that applies decides:
1. port not in `view.roles` → conflict *has no port*;
2. role not (`protocol == "iSCSI"` and `type in ("host", "free")`) → conflict *not an iSCSI port*,
   words `f"{r.mode} {r.state} {r.type} {r.protocol}"`;
3. the port's `IscsiPortAddress.peer_enabled` → conflict *peer-enabled*;
4. a `view.vlans` row with the same port and VLAN: same address, same prefix length (compare as
   `_mask_matches` in `partnership.py`) and, when the row names one, the same gateway → exists;
   otherwise conflict *already has VLAN*;
5. the address is the management address, an iSCSI port's base address, another VLAN interface's
   address, or a key of `other_addresses` → conflict *already in use*, where = `management`,
   `iSCSI port <nsp>`, `iSCSI port <nsp> VLAN <v>`, or the dict's value;
6. the request's network equals the network of this port's base address or of the management
   address → conflict *network taken*;
7. otherwise create, with `cli` = the CLI create form from step 0 (until then the string
   `"(CLI form: capture help controliscsiport)"` plus port and VLAN, so the test's `nsp in cli` and
   `"120" in cli` hold) and `wsapi` per ADR 0017 (empty until decided).
Blockers are the conflict reasons. Notes: for each VLAN ID in the requests, if all its ports are on
one node, *"VLAN <v> is only on node <n>. If that node stops, hosts on VLAN <v> lose every path."*;
for each create on a port whose role state is not `ready`, the offline note of R3.
`switch_handoff`: one sentence per port that has any create or exists action, in port order, VLANs
from the plan **and** `view.vlans` on that port, ascending, joined by `", "`, exactly
`f"Switch port cabled to {view.name} {nsp}: carry VLAN {list} tagged (802.1Q)."`. No switch command.
`removal_lines(outcomes)`: `created` only, last first, the delete form from step 0.
Turns green: every test under *R3* and *R5*.
