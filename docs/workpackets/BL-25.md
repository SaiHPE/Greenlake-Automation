## Goal

The engineer lists VLAN-tagged iSCSI addresses on a new *iSCSI network* tab; the tool plans them
against what the array has, adds them after the operator approves, gives the undo lines, checks them
in Verify and writes them into the as-built. The switch side is a sentence for the network team; the
tool never writes a switch.

## Decisions already taken (do not reopen them in code)

- Scope, sheet columns, every refusal and conflict sentence, plan states, step placement: SPEC-024.
- Reads use the read-only SSH client; no read allowlist change (SPEC-024 R2).
- iSCSI ports only. Never change a port's role, an existing VLAN interface, or the untagged address.
- The write plane is **decided** (ADR 0017, accepted 2026-11-17): the CLI `controliscsiport` forms
  (option C), on ADR 0025's one array-port write client, shared with BL-26 (ADR 0018) and ADR 0024
  part B, built from the approved plan's (port, form family) pairs; **not** on `ArrayRcCliClient`.
  WSAPI (option A) is a later swap, once an OS 10.5 write is documented and probed.
- Every form carries `-vlan` with a tag of 1 to 4094: the plan's lines, the client's forms and the
  removal set. Without it `addr` and `delete` act on the port's untagged address and cut off the hosts
  logged in on it.
- The first slice (steps 1 to 7) has no write client, no tick and no apply button. Do not start step 9
  (the apply) until step 8 (the live confirmation) holds and the owner has said yes.
- Shared with SPEC-025 (BL-26, peer ports): `PortRole` from `parse_showport_roles` is the one source of
  a port's role. If SPEC-025 merged first and already added an *Array ports* step, add a section to
  it instead of a second step.

**Step 3 — The plan.** `plan_iscsi_vlans(requests, view)` in `iscsi_network.py`, pure. Per request, in
order, the first that applies decides:
1. port not in `view.roles` → conflict *has no port*;
2. role not (`protocol == "iSCSI"` and `type in ("host", "free")`) → conflict *not an iSCSI port*,
   words `f"{r.mode} {r.state} {r.type} {r.protocol}"`;
3. the port's `IscsiPortAddress.peer_enabled` → conflict *peer-enabled*;
4. a `view.vlans` row with the same port and VLAN: same address, same prefix length (compare as
   `_mask_matches` in `partnership.py`) and, when the row names one, the same gateway → exists;
   otherwise conflict *already has VLAN*;
5. the address is the management address, an iSCSI port's base address, another VLAN interface's
   address, or a key of `other_addresses` → conflict *already in use*, where = `management`,
   `iSCSI port <nsp>`, `iSCSI port <nsp> VLAN <v>`, or the dict's value;
6. the request's network equals the network of this port's base address or of the management
   address → conflict *network taken*;
7. otherwise create, with `cli` = the array's own forms (rack13-ARCUS help, pinned by
   `test_the_array_help_names_the_vlan_add_gateway_and_delete_forms`):
   `f"controliscsiport addr {ip} {netmask} -vlan {v} -f {nsp}"`, plus, when the row has a gateway,
   a second line `f"controliscsiport gw {gw} -vlan {v} -f {nsp}"`, joined by `"\n"`. No WSAPI call
   (ADR 0017). Never a form without `-vlan`: it would change the untagged address.
Blockers are the conflict reasons. Notes: for each VLAN ID in the requests, if all its ports are on
one node, *"VLAN <v> is only on node <n>. If that node stops, hosts on VLAN <v> lose every path."*;
for each create on a port whose role state is not `ready`, the offline note of R3.
`switch_handoff`: one sentence per port that has any create or exists action, in port order, VLANs
from the plan **and** `view.vlans` on that port, ascending, joined by `", "`, exactly
`f"Switch port cabled to {view.name} {nsp}: carry VLAN {list} tagged (802.1Q); keep the untagged (native) VLAN as it is."`.
No switch command.
`removal_lines(outcomes)`: `created` and `failed` (both were sent, and ADR 0025 writes the line before
the send), last first, `f"controliscsiport delete -vlan {v} -f {nsp}"` (without `-vlan` it deletes the
port's whole configuration).
Turns green: every test under *R3* and *R5*.
