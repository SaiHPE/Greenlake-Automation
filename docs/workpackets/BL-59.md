## Rules every slice keeps (the traps)

1. **Behaviour does not change** (SPEC-030 R14). Same API calls, same arguments, same gates, same
   events read. You move and fold things; you do not remove them. List every control you moved in
   the pull request ("was → now").
2. **Steps come from the registry** (AGENTS rule 5). Never write a step list, a step count or a
   step label in a component. A step's state comes from `useStepState`; never keep a copy.
3. **Write ticks keep their exact words** and stay next to the button they unlock (LESSONS 7). A
   write button without its tick must still refuse with nothing sent. **The tick belongs to the
   plan on screen (BL-52):** `ProvisionStep` and `ReplicationStep` keep `authorisedFor` (the ticked
   plan's `plan_id`); the apply sends the id only when the plan on screen was ticked. When a tick
   moves, pass `checked: authorised` and `onChange: (on) => setAuthorisedFor(on ? planId : null)`
   as they are; never a plain boolean of your own.
4. **Frozen words** (SPEC-030 R10 lists them by step and state). The labels the lab scripts press:
   *Build plan*, *Rebuild plan*, *Create storage objects*, *Verify paths*, anything starting
   *Continue with* / *Continue to*, the tick starting *I have reviewed this plan*, *Undo what this
   run created*, *Activity*, *Console (N commands)*, *Run*, the field *Read-only command*, *Runs*,
   *Your runs*, every rail label. Footer buttons stay `<footer>` buttons. **And the text they
   read** (*No plan yet*, *Tick the box first*, *N created*, *What the array answered*, *Verify the
   paths next*, *Creation reported an error*, *Removal command set*, *Cover details* and the rest).
   A closed section renders nothing: never fold a frozen string away in the state a script reads
   it. Once T1 is in, its test fails when a frozen literal leaves `frontend/src`.
5. **Commands are byte-identical.** Zoning command sets, removal sets, the failover way back: same
   lines, same headers, same order, same Copy and Download text. The activation block (`cfgsave`,
   `cfgenable`) stays apart from the paste block and marked (LESSONS 31, ADR 0012).
6. **A section opens by itself only when it holds something to act on** (SPEC-030 R6). `Section`
   reads `open` once: key it on the condition (see `ProvisionStep`'s `key={plan ? ...}`).
7. **Keyed remounts stay.** `ZoningPlanView key={planEvent?.event_id}` and the credential card's
   key are deliberate (aliases and the form are seeded once).
8. **A stale discovery stays visible** on SAN zoning and Provision storage (LESSONS 8).
9. **No hex, no px.** Theme tokens and t-shirt sizes only (UX-GUIDELINES §2, §10). No `disabled`
   on buttons; use `blocked` or do not draw the button. One primary per screen, in the footer.
10. **No real names or addresses** in mockups or screenshots: `DEMO-ARRAY-01`, `esx-demo-01`,
    `192.0.2.x` (LESSONS 21). Crop or blur lab screenshots.

## How every slice is checked

1. From the app folder: `PYTHONPATH=$PWD/src ~/.venvs/alletra-onboard/bin/python scripts/check.py`
   (or `.venv/bin/python scripts/check.py`) says PASS. It runs `npm run typecheck` and, once T1
   is in, the frozen words test.
2. If you changed `frontend/mockups`: `cd frontend && ./node_modules/.bin/tsc -p mockups --noEmit`.
3. Screenshots through the app (`onboard ui`, then `cd frontend && npm run dev`), on a run built
   from the captured fixtures, at **1366 x 768 and 1080 x 720**, of every state the slice names,
   before and after. Attach them to the pull request. On each: the header, status line, the start
   of the current part and the whole footer are visible without scrolling (R13).
4. Keyboard only: Tab reaches every control, Enter and Space open every toggle, focus is visible.
5. Search the changed screens for the banned words (R10): health, WSAPI, SSE, n:s:p, VV-set,
   dropdowns, to-be-created, fabric-login.
6. The pull request says *built, pending live run*. The owner decides when the lab scripts run:
   `lab/ui_live_lab.py` (read-only), `lab/ui_provision_lab.py` and `lab/failed_apply_lab.py` (both
   write `zz_*` objects and remove them).
