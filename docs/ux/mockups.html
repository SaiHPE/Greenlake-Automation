Rules these screens follow

Wizard anatomySticky bar with Previous step and Cancel run; “Step X of Y”; the primary action sits far right in a footer that never moves.
Never say “health”The DS forbids it in UI copy — always “status”. The old “Verify config & health” step is now “Verify configuration”.
Status = 3 of 4 signalsColour, icon, shape, words. Ours carry all four.
Layered backgroundsOne approach app-wide; sections separated by surface colour and spacing, not borders.
Verb + noun buttons“Create storage objects”, “Run discovery”, “Download document”. Create means “submit input and make the object”.
DataTableControls above the table, a summary count in the footer.
NameValueListFor metadata, sentence-case names — used for parsed sheet values and array facts.
One spinnerNever more than one on a screen; skeletons hold layout while data loads.
VoicePlain English, active, short, roughly grade 7, sentence case, no “please”.

Where we deliberately differ

Not a fullscreen modalThe DS wizard is a modal over a page. Ours is the whole application — there is no page behind it.
We keep a step railThe DS wizard is linear and forward-only. Our steps are chosen by mode, gated by the operator and revisitable, so the rail is the only thing showing scope and position. We add “Step X of Y” so the progress rule is still met.
Cancel means discard the runThere is nothing to return to, so Cancel run ends the run — and gets the DS double confirmation.
